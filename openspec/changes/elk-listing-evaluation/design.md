## Context

The ad test proved the audience clicks (3.09% CTR on Etsy-listing-help keywords) and the embroidery framing loses them on landing. This change inverts the ELK funnel: a free, honest evaluation of the visitor's own listing becomes the front door, and the paid offer — grown from image pack to full listing kit (photos + suggested title + tags + alt text) — becomes the remedy the evaluation report recommends. The scoring rubric is inherited from the `etsy-zero-sales-funnel` discovery (Tier A publishability gate + Tier B completeness), not redesigned here.

**Draft ≠ production delta, stated up front:** the proposed frames show a **real Watermark & Hue listing** — "Custom Engraved Pet Keychain" (listing 4522917501, from the sync pipeline's captured snapshot, 2026-08-30): 2 of 10 photo slots used, no video, alt text missing on both photos, a 28-of-140-character title. Every fix-list row in the frames is true, and the frames carry the listing's two real photos (CDN assets from the snapshot). The completeness % (48%) is an illustrative placement pending the shared rubric's real weights.

## Goals / Non-Goals

**Goals:**

- Make evaluation the primary above-the-fold action (URL paste → check), replacing upload as the entry point.
- Present the verdict in two honest registers: hard PASS/FAIL on Etsy's required fields, then a completeness % with a ranked fix-first list.
- Make every recommendation carry its own current-state report, and resolve the whole report into one full-listing-kit offer beneath it — remedy in context, not banner.
- Retire embroidery framing on every surface while keeping the existing ELK palette (terracotta / ochre / cream, Fraunces + Inter) so the pivot doesn't read as a rebrand.

**Non-Goals:**

- No redesign of the upload → preview → checkout flow itself (copy de-niche only).
- No seller accounts, OAuth, or email capture around the evaluation.
- No shop-level (multi-listing) evaluation UI in v1 — one listing per check.

## User flow / IA

1. **Land** → hero asks "Is your listing actually finished?" with a single URL field + "Check my listing →". Secondary underlined link: "Just want the photos? Skip straight to the $3 image pack ↓" (jumps to the existing upload flow, which remains on the page below).
2. **Check** → server fetches the public listing; loading state on the button. A **shop link** doesn't fail — it pulls that shop's featured listing onto a confirm card ("Check this one →" / "paste a different listing"). Only genuinely unusable URLs (non-Etsy, inactive, private, fetch failure) render a plain-language reason; nothing is scored either way until a real listing is confirmed.
3. **Read the verdict** → listing identity card (real photo + title, "read from your public listing just now") → one contained **"Your listing today" card**: identity row, then "Etsy's required fields — PASS ✓, all 10 set" beside "Etsy's recommended extras — 48% in use" (ochre bar), closed by an explainer: required fields are pass/fail and get you published; the percentage grades only Etsy's recommended checklist → "Your biggest opportunities" as four **report cards**, each recommendation sitting on its own current-state evidence: (1) photos — the listing's real images in a 20-slot strip beside dashed empties; (2) title — the actual title quoted with a 28/140 character meter, plus the free sample suggested title; (3) alt text — each photo thumbed with a "no alt text" chip, kept adjacent to the images it annotates; (4) video — a dashed empty video slot, "0 videos found", deliberately last. Severity chips carry over (BIGGEST LIFT / QUICK WIN / WORTH IT). The evidence is what makes the verdict believable: the visitor sees their own listing's state before any recommendation asks anything of them.
4. **Meet the offer** → beneath the report cards, one **full listing kit** card resolves everything above: "⚡ THE FULL LISTING KIT — Every fix above, done for you" listing six photos, a suggested 140-character title, 13 suggested tags, and alt text for every photo, plus a listing-video line dimmed with a COMING SOON chip (teased, not built). Foot: "yours to paste into Shop Manager — we never touch your shop." CTA "Build my listing kit →" scrolls into the fix flow below (instrumented as pack-offer-click).
5. **Fix with the kit** → the upload flow reframed as the remedy, with the evaluation's context carried in: back link ("← Back to your check"), heading "Fix the photo gap", sub naming the visitor's actual listing and its gap count. Below: the existing dropzone → watermarked 6-preview grid → $3 pay panel, mechanics unchanged, copy tied back to the gap ("ready for those empty photo slots").

**Severity chips on the fix list** (rubric weight order, copy founder-editable): **BIGGEST LIFT** = the gap costing the most completeness points; **QUICK WIN** = fixable in minutes in Shop Manager (tags, alt text); **WORTH IT** = real effort but one of Etsy's core SEO elements (video).

## Decisions

1. **URL-first, upload demoted** — the dropzone no longer opens the page; it lives below the evaluation and behind the "skip to the pack" link. Sellers who already know what they want lose nothing (one anchor jump).
2. **Free and gateless** — no email wall on the check. The demand signal we need is evaluation-starts → pack conversions; a gate would contaminate the very funnel the next ad burst measures.
3. **Server-side fetch, existing key** — listing id parsed from the pasted URL, fetched via the read-only Etsy API with the existing app key. No OAuth, no writes.
4. **Shared rubric module** — Tier A/B logic extracted to a module both this surface and the labs scorecard (`etsy-zero-sales-funnel`) import; fixture test pins identical output through both entry points.
5. **Evaluations persist** — a small `elk_evaluations` table (listing id, scores, timestamp) so the funnel read doesn't depend on GA4 alone; no buyer/account data.
6. **The offer speaks to design sellers** — "made from your design" targets sellers of patterns/prints/design-based goods, the segment the kit genuinely serves today. The evaluation itself is universal; broadening the pack (photo mockups for physical goods) is future scope, not v1.
7. **W&H is the testbed, and testing must not touch Etsy (founder, 2026-08-30)** — all example data and dev/test evaluations run against **Watermark & Hue's own listings**, and by default against the sync pipeline's **already-captured snapshots** (Supabase `etsy_latest_listing_snapshots`) — zero new Etsy calls during development, so no rate-limit or security-flag exposure. Concretely: rubric tests use fixtures exported from snapshots; a dev fixture mode serves the evaluation UI from snapshot data; live-fetch code paths are exercised only in the final manual walkthrough, against a small number of W&H listing URLs, through the official v3 API with the existing app key (no scraping, no unauthenticated endpoints). Production adds a server-side per-listing cache (repeat checks of the same listing within the TTL don't re-fetch) and a per-IP throttle on the check endpoint.
8. **Shop URLs suggest, not scold (founder, 2026-08-30)** — pasting a shop link (the most natural first move, e.g. `etsy.com/shop/WatermarkandHue`) pulls the shop's **featured listing** onto a confirm card — "here's the listing that shop features: Check this one →" — with a "paste a different listing" alternative; nothing is scored until confirmed. Only genuinely non-Etsy URLs get the plain failure. A full shop-URL → listing-picker stays future scope. Exemplar in frames: W&H's featured "Beginner Botanical Embroidery Design, Floral Hoop Art Pattern" (listing 4465357735). The URL parser must also tolerate real-world tracking clutter — listing URLs arrive with `ref=`, `sr_prefetch=`, `logging_key=` etc.; the listing id segment is the only thing that matters.

9. **Evidence comes from data, not page screenshots (2026-08-30)** — the founder asked for the listing "as a screenshot" plus its images; attempting it surfaced the constraint: Etsy serves a bot-verification wall to both headless Chrome and a clean automated browser profile (CAPTCHA — never bypassed, attempt stopped immediately). Production would hit the same wall server-side, so a page-screenshot feature would be fragile and flag-prone by design. The substantive-evidence job is met from the fetched data itself: the evidence strip renders the listing's **actual photos** (CDN image URLs the API already returns — static assets, no bot surface) beside its empty slots, and the identity card carries the real primary image. Frames now use the keychain listing's two real photos and the floral listing's real photo on the suggestion card.

10. **Every recommendation carries its report; the sellable is the full kit (founder, 2026-08-30; page 02.10)** — each fix row is now a **report card** whose evidence is the listing's own current state: photos beside their dashed empty slots; the actual title quoted with a 28/140 character meter; a dashed empty video slot; per-photo "no alt text" chips. The offer beneath resolves the report: **the full listing kit** — six photos + suggested 140-char title + 13 suggested tags + alt text for every photo, delivered as paste-ready suggestions (no Etsy writes, per the "we never touch your shop" foot). A **listing-video add-on is teased with a COMING SOON chip** — visible demand probe, zero build (founder: tease it so it needn't be built yet). Kit **pricing is an open founder decision** — frames render today's $3 pending that call.

11. **The free evaluation gives one real taste of the kit, and every claim cites Etsy (founder, 2026-08-30; page 02.11)** — the title report card now includes a **free sample suggested title** for the evaluated listing (“FREE SAMPLE — WHAT THE KIT WOULD SUGGEST”, 130/140 characters) — the freebie that proves the paid kit is real. And each report card closes with a **quoted excerpt from current Etsy documentation, its source, and a “checked <date>” stamp**. Implementation: a citation registry in code — `{quote, sourceTitle, sourceUrl, lastCheckedAt}` per criterion — rendered on the cards; the date proves the rubric tracks living guidance. **Verification constraint:** etsy.com and help.etsy.com return 403 to automated fetches, so quotes were sourced via search excerpts on 2026-08-30; verbatim confirmation of each quote in a real browser is an explicit apply-time task, and re-checking the registry becomes a recurring maintenance touch.

12. **Photo cap corrected to 20 assets (founder, 2026-08-30)** — Etsy now allows up to **20 photos & videos per listing**; the founder confirmed it, current Handbook guidance agrees, and W&H's own mandala listing carries 13 photos (impossible under a 10 cap). 13. **Video is the last recommendation (founder, 2026-08-30; page 02.12)** — report order is photos → title → alt text → video. Two reasons: alt text belongs with the images it annotates, and video is the one gap the kit doesn't fix yet (it's the COMING SOON tease) — so the un-actionable recommendation sits last, directly above the kit card where its "coming soon" line explains itself. Blank slots for what only the seller knows ship in the template file. All 11 exemplar tiles on 02.26 are real pipeline renders (sharp + bundled fonts) from the keychain fixture. ## Risks / Trade-offs

- **Pack-audience mismatch:** the evaluation invites *all* Etsy sellers; the pack currently fits *design-file* sellers. Some evaluated visitors have no design to upload. Mitigation: offer copy is explicit, and pack-offer-click vs. upload-start instrumentation will show the gap's size — that data feeds the next pivot decision instead of guessing now.
- **Etsy API posture:** evaluating third-party public listings with the app key is read-only public data, but rate limits and ToS tone deserve a check during apply; a per-IP throttle on the check endpoint is cheap insurance.
- **Rubric caveats carry over:** the † thresholds (photo 10, tags 13, title 140, materials 13) still carry the "verify in Shop Manager" caveat from the discovery — verify before locking scores that strangers will see about their own shops.
- **Honesty risk:** a wrong score shown to a stranger's listing is worse than no score. The shared-module fixture test and the fail-honest empty states are the guardrails; when in doubt the UI says "couldn't read this listing" rather than guessing.
