# scoring-impact-rubric — design

## Context

The rubric edit (Personal / Social / Business Impact, 1–5 each) needs a visible home. Discovery during design changed the shape of the work: the five-dimension score display (`components/ExperimentScores.tsx`) is dead code — imported nowhere — and the landing "Scaffolding" cards section is already commented out. The only live score UI today is the landing list's total badge. So this design adds one new surface (the detail-page Impact block, which finally gives scores and justifications a visible home), edits one (header nav), and deletes three routes plus dead code.

## Goals / Non-Goals

**Goals:**

- Impact block on the experiment detail page: three dimensions, 5-step dots, `n/5`, justification prose, total `n/15` — in the detail page's existing visual language (uppercase tracked labels, 720px measure).
- Header nav reduced to `Experiments` — Scoring/Heuristics/Harness items removed with their routes.
- Landing badge and sort become shape-aware (`n/15` impact rows, `n/25` v1-history rows).
- Scores and justifications editable in the existing BHD Labs Projects Notion database.

**Non-Goals:**

- No new rubric documentation page (rules file is the source of truth).
- No revival of the dead five-dimension display — it's deleted, not migrated.
- No redesign of the detail page beyond inserting the Impact block.
- No Supabase schema work — the Supabase fallback stays v1-only for now (risk noted below).

## User flow / IA

1. **Score in Notion:** Katy opens the experiment's row in BHD Labs Projects, fills three number columns and three justification text columns.
2. **Hub reflects it:** the detail page Overview shows the Impact block between Statement and History; the landing list badge shows the `n/15` total (sortable), tooltip naming the three dimensions.
3. **v1 history rows:** unchanged behavior — landing badge shows `n/25` with a tooltip labeling it the v1 historical record; detail pages (which never showed per-dimension scores) stay as they are.
4. **Removed routes:** `/scoring`, `/heuristics`, `/harness` return the app 404; header nav no longer offers them.

## Decisions

1. **Shape discriminator = separate fields, no sniffing.** `Experiment` gains `impactScores?: { personal; social; business }` (1–5 each) and `impactRationale?: { personal?; social?; business? }`, alongside legacy `scores`/`scoreRationale` which stay typed as-is. Presence of a complete `impactScores` wins everywhere.
2. **Notion storage:** scores are three number columns — `Score:PI` / `Score:SI` / `Score:BI` — on the existing Labs database, mirroring the `Score:B…S` naming so the row reads as one family. Created via the Notion connector at apply time, schema-only, confirmed with Katy immediately before the call. **Justifications are full Notion pages, not table fields:** each is a child page of the experiment's row page, titled `Why: Personal` / `Why: Social` / `Why: Business` (titles as exported constants beside the column names). Katy writes as little or as much as she wants — one paragraph or a complete business case with headings and lists. The sync lists the row page's child blocks, matches those titles, and fetches the matched page's block content; a missing page simply means no tab. Supported blocks rendered on the hub: paragraphs, headings 1–3, bulleted/numbered lists, quotes, dividers — anything else is skipped with its plain text preserved.
3. **Totals:** `calculateTotalScore` (v1) stays untouched; new `calculateImpactTotal` returns 3–15 or null. Landing badge/sort resolve via impact-first helper. `getTotalBadgeColor` rescales by normalizing total/max rather than hardcoded 5–25 thresholds.
4. **Display home:** new `components/ImpactScores.tsx` rendered on the detail page between Statement and History, matching the Statement visual language (uppercase 12px tracked label, dark text on light, 720px measure). Layout per Figma `02.6`/`02.7`: an `IMPACT SCORE n/15` heading (full-measure row, 12px gap, per Katy's 02.7 edit), 8px to the four-tab bar (active = dark text + 2px accent underline, echoing the header-nav active treatment) with the selected content below as full-width prose, 14px/1.7, paragraph breaks and block structure preserved. There is no separate score ledger — each dimension tab's badge chip IS the score display (the 1–5 dots pattern is retired with it). Dimension tabs render even without a `Why:` page (badge only, empty-state note in content); with no scores at all the block doesn't render. Each dimension tab's content opens with its 1–5 anchor legend as a white card above the justification (per Katy's `02.8` rework: `bg-white rounded-lg p-4`, rows dark green, scored anchor bold / others regular) — the rubric stays readable in place now that `/scoring` is gone. Anchor strings live once in code (e.g. `lib/rubric.ts`) shared by the component; a vitest guard asserts they match `rules/scoring-criteria.mdc` so the two can't drift (the acceptable, tested exception to the no-second-copy rule). The tab switcher is a small client component; the rest of the detail page stays server-rendered. Dead `components/ExperimentScores.tsx` is deleted.
   **Overview layout (per `02.4`, Katy's pick):** single column — Statement, score ledger, then a four-tab bar: Personal / Social / Business / **History**. Each dimension tab label carries a small score badge chip; History has no badge. Spacing per Katy's `02.7` edit (13:83): tabs `p-4` (16px all sides, 6px label↔badge gap), badge chip 10px×8px padding, 4px radius, accent-tint background, 11px semibold score number. The three dimension tabs render their justification pages; the History tab renders the dated milestone list (88px date gutter + sentence, as today). The standalone History section is removed from the Overview; at S·480 the same single column simply narrows.
5. **Spec reconciliation (v1 history):** the spec's "five-dimension display renders as it does today" was written before discovering that display is dead code. "As it does today" for v1 rows = the landing badge only; it gains a tooltip labeling it `v1 rubric · historical`. The five-dimension component is deleted, not revived. Spec scenario wording updated to match; flagged for approval with this design.
6. **Landing tooltip:** replaces "…across five scoring dimensions — see /scoring" with shape-aware text naming the three impact dimensions (impact rows) or the v1-history label (v1 rows); the dead `/scoring` reference goes away.
   **Landing sub-score columns (Katy, 2026-08-14, directed from the live table during apply):** the PRD / Landing / Prototype presence columns are replaced by Personal / Social / Business sub-score columns — accent-tint chip per score, sortable, dash for v1-only/unscored rows. Presence data (`hasPRDFile` etc.) still flows from the server; dropping that plumbing is follow-up cleanup.
7. **Rubric file:** rewritten as v3 with 1–5 anchors — Personal and Social carried from v1, Business merged from `businessOpportunity` + `competitiveAdvantage` with evidence-of-demand + differentiation anchors (no TAM dollar gates). Re-grade line format: `**Predicted:** PI4 SI3 BI2 · **Actual:** … · **Missed:** …`; `skills/openspec-archive-change.md` example updated to match.

## Risks / Trade-offs

- **Notion column-name drift** breaks the sync silently (properties read as absent → rows appear unscored). Same for `Why:` child-page title drift — a renamed page silently drops its tab. Mitigated by exported name constants + mapping tests with real property/block fixtures.
- **Extra Notion API calls per detail view** (child-block listing + one page fetch per justification on a force-dynamic route). Mitigated with a short-TTL memoized cache, same pattern as `loadOpenSpecLifecycle`.
- **Supabase fallback stays v1-only:** if Notion is down, impact scores vanish from the fallback render (rows fall back to v1 badge or unscored). Accepted for now; a `score_impact` Supabase column is a follow-up if it ever matters.
- **Direct links to removed routes** (old bookmarks, analytics history) will 404. Acceptable — these were internal-documentation pages; the ELK analytics comment referencing `/heuristics` is prose only.
- **Badge color rescaling** subtly changes badge colors for v1 rows if thresholds normalize differently — verify against current renders in tests.
